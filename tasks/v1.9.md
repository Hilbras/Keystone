## Verified upgrade path

Against a database migrated to 1.8 and seeded with a platform owner:

1. `SCIM_BEARER_TOKEN` / `SCIM_ORG_ID` are adopted once into a connection whose
   stored digest matches the legacy token, and the token authenticates.
2. Revoking the connection and restarting does **not** re-create it: the legacy
   variables are ignored, the connection stays revoked, and the token stops
   authenticating.

## Requirement notes

- **Req 4 (repository methods).** `findByIdInOrg`, `updateInOrg`,
  `listOrgIdsForUser`, and `removeFromOrg` exist. The route layer no longer
  imports `db` directly.
- **Req 3 (groups).** Implemented as real organization-scoped records. The old
  role-bucket projection was removed because it could not express membership,
  deletion, or search; see `docs/MIGRATION-1.9.md`.
- **Deprovisioning.** A user row is global, so deletion removes the membership
  first and deactivates the account only when no membership remains anywhere.
  Deactivating a shared account would revoke access to organizations this
  credential has no relationship with.
