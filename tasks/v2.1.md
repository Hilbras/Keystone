## Findings

Plan items 1 and 2 were already satisfied. The real work was items 3 to 5.

1. **Four moderate advisories in the development tree.** `drizzle-kit` pulls
   `@esbuild-kit/esm-loader`, which pins its own `esbuild@0.18.20`
   (`GHSA-67mh-4wv8-2f99`, fixed in 0.25.0). Not exploitable here: the advisory
   needs esbuild's `serve()` API, which Keystone never calls, and the packages
   are `devDependencies` with `npm audit --omit=dev` already clean. Still a real
   advisory in the tree that builds the published artifact, and
   `npm audit fix --force` offered only a breaking downgrade of `drizzle-kit` to
   0.18.1.

2. **`package.json` declared no `license` field**, despite shipping an MIT
   `LICENSE` file. The published package carried no machine-readable terms.

## Container image finding

The new container scan found **8 HIGH-severity advisories in the published
image** that `npm audit` and OSV both correctly missed, because neither reads
the base image.

Attribution was traced rather than assumed. All five distinct packages matched,
to the byte, the versions bundled in `node:22-slim`'s `npm@10.9.9`:

| Package | In base image's npm | In Keystone's tree |
| --- | --- | --- |
| brace-expansion | 2.0.2 | 5.0.12 (already patched) |
| ip-address | 10.1.0 | absent |
| pacote | 19.0.2 | absent |
| picomatch | 4.0.3 | absent |
| sigstore | 3.1.0 | absent |

The runtime image never invokes npm: `CMD` is `node dist/index.js`, and the
development compose override builds the `builder` target, which keeps its own
npm. So npm is now removed from the production stage.

## Supply chain workflow defects found by running it

Three defects would have left the gate permanently red, which is how a security
gate gets ignored. All were found by running the workflow, not by reading it.

- `aquasecurity/trivy-action@0.30.0` does not exist; the action's tags carry a
  `v` prefix. Container scanning failed to resolve in 3s every run.
- `fail-on-license` is not an input of `dependency-review-action`; the real
  inputs are `allow-licenses` and `deny-licenses`. The intended denylist was
  being silently ignored.
- Dependency review requires the repository's dependency graph, a Settings
  toggle that cannot be set from a workflow file. It now checks availability
  first and emits a `::warning` naming the setting, so an unconfigured
  repository skips the check instead of failing every pull request. Verified
  the guard detects the current state: the REST endpoint fails and GraphQL
  reports `dependencyGraphManifests.totalCount: 0`.

A fourth defect, in `ci.yml`, meant a PR targeting a release branch ran **no
checks at all**. Release branches are where the tagged code lives, so that was
the worst place for the gap. Both workflows now trigger on `release/**`.
