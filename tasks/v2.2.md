## The three races

All three had one shape — a conditional `SELECT` followed by an **unconditional** `UPDATE`. Any number of concurrent requests pass the check, so all of them succeed:

- **Magic links** — parallel redemptions each produced a full login. A link meant to be usable once was usable indefinitely under concurrency.
- **Password reset tokens** — parallel resets each wrote a different password, last writer winning. Most consequential of the three: whoever won held the account, and an attacker racing the legitimate user could take it over.
- **SMS OTP** — a six-digit code was not single-use under concurrency.

## Fix

`src/services/singleUse.ts` — one primitive that makes the write the gate:

```sql
UPDATE <table> SET used_at = now()
WHERE <hash> = ? AND expires_at > now() AND used_at IS NULL
RETURNING *
```

PostgreSQL evaluates that predicate while holding a row lock, so exactly one transaction updates the row and sees a returned row. Claim and validation become one statement with no window between them.

Drizzle's column generics cannot express "any table with these three columns", and the alternative is a cast per call site — three places to get the predicate wrong instead of one. The cast is confined to a single documented function, and the concurrency tests are the proof the predicate it writes is correct.

## Replay detection (plan item 3)

A credential presented after it was spent now emits `magic_link_replayed`, `sms_otp_replayed`, or `password_reset_token_replayed`. All three reach the audit log: the event bus uses `subscribeAll` for the audit-log subscriber, so no per-event registration was needed.

An **expired** credential is deliberately not reported as a replay — expiry is not a leak. A token that never existed is reported only as invalid, so the endpoint is not an oracle for which tokens once existed.

## Regression verification

Every claim below was checked by reverting the fix and observing the test fail, not by reading the diff.

| Reverted | Test result |
| --- | --- |
| `consumeMagicLink` to the racy shape | `expected 1 login, got 50` |
| `resetPasswordWithToken` to the racy shape | `expected 1 successful reset, got 50` |
| The `magic_link_replayed` emit only, atomicity kept | `expected magic_link_replayed, saw: nothing` |

The suite also contains `The racy pattern this replaced`, which reproduces the old read-then-write shape verbatim and asserts that it *does* let several callers through. If the shape ever returns, the reason it was removed is documented in a test that fails.
