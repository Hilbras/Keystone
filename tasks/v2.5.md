## Findings

| 1 | `GoogleConnector.exchangeCode` did not forward `opts`, discarding the OIDC nonce | **Live.** Defeated 2.4.0's nonce check for the default provider |
| 2 | The response-level SAML `Issuer` is unsigned and was never validated | **Live** |
| 3 | `verifyRelayState` threw on a missing signature, turning a 400 into a 500 | **Live** |

### Finding 1 is a regression in combination

2.4.0 added nonce validation. `GoogleConnector` already overrode `exchangeCode`,
and the override did not forward its options — so the nonce was dropped before it
reached the base implementation. The 2.4.0 tests exercised `OidcConnector`
directly and never covered the override, which is why it passed CI.

This is the failure mode of testing a base class rather than its subclasses.

### Finding 2: establishing the gap was not obvious

Rewriting the `Issuer` in a test fixture appeared to be *accepted*. Two things
were going on:

1. The response-level and assertion-level `Issuer` elements are separate. A
   `.replace()` changes only the first, and that one is outside the signature.
2. Rewriting **all** issuers does break the signature, so the naive version of
   the test passed for the wrong reason.

A probe confirmed `Issuers INSIDE signed region: NONE`, and that replacing all of
them yields `FAILED_TO_VERIFY_SIGNATURE`. So the response-level issuer really is
unsigned and really was unvalidated, and the fix is a direct comparison against
the registered IdP entity ID.

## Fixes

- `GoogleConnector.exchangeCode` forwards `opts`; the nonce reaches the base.
- `GoogleConnector.resolveUserinfoEndpoint` returns `undefined` when unconfigured
  instead of forwarding a non-null assertion into the fetcher.
- `validateSamlSemantics` compares the issuer to `connection.idpEntityId`.
- `verifyRelayState` returns false for any malformed input rather than throwing.
- `signRelayState`, `verifyRelayState`, and `RelayStateSchema` exported for test.

## Tests corrected rather than forced

Two of my own assertions were wrong and the code was right:

- I asserted plaintext HTTP was always refused by the SSO endpoint validator. It
  is deliberately allowed outside production for local development. The test now
  asserts against the loaded `config.NODE_ENV` and logs which branch it took,
  because `config` is a load-time snapshot and cannot be flipped mid-process.
- I used `http://localhost:9000` to isolate the HTTPS rule, which is refused for
  being a *private* address instead. Switched to a public hostname so the two
  rules are tested independently.

Also removed three throwaway probe files from `dist/` that a `git check-ignore`
confirmed could not have been committed — they had been left by debugging and
picked up by the test glob.
