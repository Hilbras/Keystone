## The finding: two registry entries were not real

Generating the re-audit matrix instead of writing it immediately paid for itself.
The SAML hardening row came back **Fixed: No**, and the reason was that two
entries named fixes in `src/services/saml/validator.ts` and `src/routes/sso.ts`.
There is no `src/services/saml/` directory.

Checking the two suites those entries pointed at:

- `saml-validator.test.ts` exercises the **valid** signed-response path. It does
  not test a missing audience or issuer requirement. There is no such fix.
- `sso-endpoint.test.ts` tests `isPrivateAddress`, a guard on operator-supplied
  endpoint addresses. It does not test an unregistered host alias. There is no
  such fix.

So `SEC-043` and `SEC-044`, added during the 2.9.0 release, described defects that
do not exist, at paths that do not exist, and the registry reported itself
healthy.

## Why it passed

The validator checked that the entry's named **test** existed, and that the test
file contained a test. It never checked the **fix** field — the part of the entry
that makes the claim. So an entry could name any real test file and any
plausible-sounding fix location and be accepted.

That is the same failure mode this programme has hit repeatedly: a control that
exists and does not cover the thing it is assumed to cover. Fourth occurrence.

## What changed

1. **Two entries withdrawn**, not deleted. `registry.withdrawn` records the id, the
   date, the reason, and what replaced it. Ids are not renumbered: renumbering
   changes every id other documents already cite, and a registry whose ids shift
   is one nobody can reference. Ids may now gap, and a gap must be explained.
2. **A `coverage` section** for suites that assert a property without an evidenced
   defect. Recording those as findings to satisfy a completeness check is how a
   registry starts asserting things nobody checked.
3. **The fix site is now resolved against the repository.** Four entries named
   paths that do not exist: the two invented ones, plus `SEC-021` and `SEC-022`,
   which described real SAML fixes at the wrong location. The SAML logic lives in
   `src/routes/saml.ts` — `verifyRelayState` at the top of the file, the issuer
   comparison mid-file. All corrected.
4. **Every new check verified by breaking it.**

| Broken | Caught |
| --- | --- |
| fix path that does not exist | yes |
| suite with neither an entry nor coverage | yes |
| id in neither entries nor withdrawals | yes |
| withdrawal with no reason | yes |
| coverage naming a missing file | yes |

## The matrix

`docs/RE-AUDIT.md`, generated by `scripts/render-reaudit-matrix.mjs`.

Each cell is verified when the file is produced. `Fixed` only if the fix site
exists. `Regression test` only if the named file exists **and contains a test**.
`Documentation` only if the document exists.

This is the difference between a table that says the programme is complete and one
that demonstrates it. Deleting a test turns the cell red on the next run.

Result: 18 plan findings, every claim verified, **zero unresolved Critical**.

Wired into three places so it cannot go stale: `npm run reaudit:check`, the test
suite, and the release gate.

## Multi-tenant review: no cross-tenant path found

Every organization-scoped admin route was traced to its guard.

- `requireOrganizationRole` reads `orgId` from `request.params.id` and calls
  `requireOrgRole(userId, orgId, ...)` — membership is checked in the *requested*
  organization, not the caller's own. This is the linchpin, and it is sound.
- Routes guarded only by `app.authenticate` were traced into the application
  layer. `GET /organizations/:id` calls `sdk.organization.getOrganization`, which
  calls `requireOrganizationPermission(userId, orgId, ...)` before returning.
- SAML and OIDC connection routes use org-scoped repository methods —
  `listByOrgId(id)`, `findByIdAndOrgId(connectionId, id)` — not bare id lookups.
- Billing and members use `requireOrganizationRole` with a resource/action
  permission.
- Permissions, webhooks, queue, feature flags and configuration profiles are all
  `requirePlatformRole("owner")`.

Recorded as verified rather than fixed, because nothing was wrong.
